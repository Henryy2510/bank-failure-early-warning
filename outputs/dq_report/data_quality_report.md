## 6. Decision matrix
| Issue | Evidence | Handling | Why |
|---|---|---|---|
| Schema drift | 14 columns | explicit cast of every column when building Bronze | stable schema, `scan_parquet` works |
| Dates stored as strings | `REPDTE`, `FAILDATE`, `ESTYMD` | parse to `Date` | date arithmetic, window joins, row-group statistics |
| Structural missing | `P3ASSET` null in 57.8% of rows | keep null, impute on training data only | missing is a reporting regime, not noise |
| YTD flows | 7 income items | de-cumulate, only if previous row is the previous quarter | true quarterly flow; no wrong lag across a gap |
| Basel zeros | `RBC1AAJ == 0` in 18.13% of pre-1990 rows | recode to null | 0 would mean zero capital |
| Negative equity | 15,659 rows | keep + distress flag; Texas ratio capped | these are the banks about to fail |
| Extreme ratios | ROA, ROE, ... | winsorise inside each training fold | a global clip would use future data |
| Merger vs failure | exit classification | merger = censored, y = 0 | healthy acquired banks are not failures |
| Publication lag | 59.1% of failures | rows that failed before availability are non-scorable | no look-ahead in training or evaluation |
| Assistance vs closure | RESTYPE | both are failure events (course definition); counts by type reported | transparent |
